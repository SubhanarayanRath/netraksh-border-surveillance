# PHASE 6: SFACE INTEGRATION

## Status
COMPLETE

## Integration Architecture
SFace has been successfully integrated as an opt-in face recognition engine, running entirely behind the `FACE_RECOGNITION_ENGINE` feature flag. The legacy `LBPH` path remains unmodified and acts as the production default.

### Component Details
- **Engine Selection**: Opt-in via `FACE_RECOGNITION_ENGINE=sface`.
- **Model Adapter**: `SFaceEmbeddingModel` inherits from `FaceEmbeddingEngine`. It executes `face_recognition_sface_2021dec.onnx` via `onnxruntime`.
- **Adapter Interface**: `WatchlistFaceRecognizer` has been transformed into a facade. It initializes either the LBPH or SFace sub-engine. 
- **Resource Pressure**: Handled correctly. If `resource_pressure=True` is passed to `recognize()`, SFace aborts execution and yields `{"status": "NOT_EVALUATED_RESOURCE_PRESSURE"}`, preventing a false identity mismatch.
- **Fallback Semantics**: Explicit configuration via `FACE_FALLBACK_TO_LBPH=true`. If SFace fails to load the ONNX model and fallback is explicitly enabled, it falls back to LBPH; otherwise, the subsystem gracefully blocks execution.

### Temporal Fusion Compatibility
Matches generated by the SFace engine return the identical dictionary structure:
```json
{
  "person_id": "...",
  "name": "...",
  "confidence": 0.85,
  "engine": "sface",
  "state": "MATCH"
}
```
This is fully compatible with the existing `TemporalFaceFusion` subsystem, which consumes it alongside other face matches.
